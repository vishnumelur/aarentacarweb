# P1.1 Foundation & Data Model Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up the Turborepo monorepo and the complete Postgres schema for AA Rent A Car, so that `pnpm db:migrate && pnpm db:seed` produces a working database with both branches, seven vehicle classes, sample vehicles and rate cards.

**Architecture:** A pnpm workspace managed by Turborepo. All database concerns live in `packages/db` — Drizzle schema split one file per domain module, migrations generated by drizzle-kit, and a seed script. No application code, no UI, no API in this plan. The deliverable is a schema that later plans build against, verified by integration tests running against a real Postgres in Docker.

**Tech Stack:** Node 24 LTS · pnpm 9 · Turborepo 2 · TypeScript 5 (strict) · Drizzle ORM · drizzle-kit · Postgres 17 · Vitest · Docker Compose

## Global Constraints

Copied verbatim from the spec. Every task inherits these.

- **Node 24 LTS.** Node 18 is deprecated.
- **TypeScript strict mode; no `any` in shared packages** (NFR-9).
- **Postgres 17** (spec §2 Stack).
- **Store UTC, render Asia/Dubai** (NFR-5). Every timestamp column is `timestamptz`. The database `timezone` is `UTC`.
- **Money is stored as integer minor units (fils).** 1 AED = 100 fils. No floating point for currency, anywhere, ever. Column type is `integer`, named with a `_fils` suffix.
- **VAT is 5%** (NFR-4), stored as basis points (`500`) in settings, never hardcoded in a query.
- **Vehicle classes are a managed table, not a hardcoded enum** (FR-17.6).
- **Rates are versioned; a booking retains the rates in force when it was made** (FR-17.7). Historic bookings never reprice.
- **Branch opening hours are a list of intervals per weekday, not an open/close pair** (NFR-5) — Friday has two intervals.
- **Invoice numbers are sequential and gapless**; a voided invoice keeps its number and is marked void (FR-15.2).
- **Handover records cannot be deleted, only superseded** (NFR-11).
- **Files stay focused; past roughly 300 lines is a signal to split** (NFR-9).
- **Seed data, never production data** (spec §9.5).
- Business identity for seed: **Auto Assist Service (AA Rentals)**, branches **Al Karama** and **Dubai Media City**, hours Sat–Thu 08:00–21:30, Fri 08:30–12:00 and 17:00–21:30.

```typescript
import { drizzle, type NodePgDatabase } from 'drizzle-orm/node-postgres'
import pg from 'pg'
import * as schema from './schema/index.js'

export function createDb(connectionString: string): NodePgDatabase<typeof schema> {
  const pool = new pg.Pool({ connectionString, max: 10 })
  return drizzle(pool, { schema })
}

let singleton: NodePgDatabase<typeof schema> | undefined

export function getDb(): NodePgDatabase<typeof schema> {
  if (!singleton) {
    const url = process.env.DATABASE_URL
    if (!url) throw new Error('DATABASE_URL is not set')
    singleton = createDb(url)
  }
  return singleton
}
```

  check('daily_rate_non_negative', sql`${t.dailyRateFils} >= 0`),
  check('deposit_non_negative', sql`${t.depositFils} >= 0`),

import {

  'DRAFT', 'PENDING_PAYMENT', 'CONFIRMED', 'DOCS_VERIFIED', 'READY_FOR_PICKUP',

  'CANCELLED', 'NO_SHOW', 'EXPIRED',
  'ASSIGNED', 'EN_ROUTE', 'ARRIVED', 'IN_TRIP', 'DROPPED',
])

  'self_drive', 'lease', 'chauffeur_hourly', 'chauffeur_transfer',
])

export const bookings = pgTable('bookings', {

  termsVersion: text('terms_version'),
  cancellationPolicy: text('cancellation_policy'),
  createdByUserId: uuid('created_by_user_id').references(() => users.id),

    ${t.subtotalFils} >= 0 AND ${t.vatFils} >= 0
    AND ${t.totalFils} >= 0 AND ${t.depositFils} >= 0`),

// Sat-Thu 08:00-21:30; Fri 08:30-12:00 and 17:00-21:30
const WEEKLY_HOURS: Array<{ weekday: number; opensAt: string; closesAt: string }> = [

  { weekday: 1, opensAt: '08:00', closesAt: '21:30' },

## What this plan deliberately excludes

- **No availability engine, pricing function or state machine.** Those are P1.2, built as pure functions in `packages/shared` against this schema.
- **No lease or chauffeur detail tables.** P2. The enums include their values so no enum migration is needed later.
- **No `apps/web`.** P1.3 onwards.
- **No MinIO bucket creation in code.** Buckets are provisioned by the runbook (§4); the schema stores object keys only.
- **No password hashing or session issuing.** P1.3. Seed users exist without credentials by design.
